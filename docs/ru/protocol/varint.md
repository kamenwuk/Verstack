# VarInt — целое переменной длины
> `src/Verstack.Protocol/VarInt.cs`

Используется по всему протоколу Minecraft: длины пакетов, идентификаторы пакетов, числовые поля.
Реализует кодирование **LEB128** (Little-Endian Base 128).

## Зачем переменная длина

Большинство чисел в протоколе невелики. Фиксированный `int32` (4 байта) расходовал бы место впустую.
VarInt занимает 1 байт для значений `0..127` и до 5 байт для больших/отрицательных чисел.

## Битовая раскладка одного байта

```
бит:    7  6  5  4  3  2  1  0
      ┌───┬─────────────────────┐
      │ C │      данные (7)     │
      └───┴─────────────────────┘
        ↑
       continuation: 1 = «есть ещё байты», 0 = «последний»
```

- **Бит 7** — флаг продолжения. Если `1`, за текущим байтом идёт следующий.
- **Биты 0–6** — полезные данные.

Данные упакованы **little-endian**: первый байт несёт младшие 7 бит, второй — следующие 7, и т.д.

## Разбор на примере: кодирование 300

Режем 300 на 7-битные куски с младшего:

```
300 = 0x12C = 1_00101100  (9 бит)
       режем по 7 бит с LSB:
       ┌─────────┬──────┐
       │ 0101100 │  010 │   ← куски (младший слева)
       │  =44    │  =2  │
       └─────────┴──────┘

накидываем continuation:
  байт 0: 1 | 0101100 = 0xAC   ← «есть ещё»
  байт 1: 0 | 0000010 = 0x02   ← «последний»

итого: [0xAC, 0x02]
```

Декодирование — обратный процесс, каждый байт вносится со сдвигом:

```
байт 0 = 0xAC → continuation выставен   → данные = 0xAC & 0x7F = 44  (биты 0..6)
байт 1 = 0x02 → continuation сброшен     → данные = 0x02 & 0x7F = 2   (биты 7..13)

значение = 44 | (2 << 7) = 44 | 256 = 300  ✓
```

Маски в ходу: `0x80` (continuation), `0x7F` (данные), сдвиг по 7 на байт.

## Краевые случаи

| Значение | Кодировка | Почему |
|----------|-----------|--------|
| `0` | `[0x00]` | Один байт, continuation сброшен. |
| `127` | `[0x7F]` | Максимум в один байт. |
| `128` | `[0x80, 0x01]` | Не влезает в 7 бит — нужен второй. |
| `-1` | `[0xFF, 0xFF, 0xFF, 0xFF, 0x0F]` | Знаковый int32 → все 5 байт. |
| `int.MaxValue` | 5 байт | Предел. 5-й байт несёт только 4 бита (биты 28–31). |

Максимальная длина — 5 байт — продиктована размером знакового 32-битного целого.
Если после пятого байта флаг продолжения остаётся `1`, данные считаются повреждёнными (`Malformed`).

## API

## Константы и типы

- `MaxSize` — максимальный размер кодированного значения (5 байт).
- `ReadStatus` — перечисление с результатами чтения:
  - `Complete` — значение успешно прочитано.
  - `Partial` — недостаточно байт.
  - `Malformed` — неверные данные (продолжение после 5-го байта).

### Методы

- `int GetByteCount(int value)` — возвращает число байт для кодирования `value` (без записи).
- `int Encode(int value, Span<byte> destination)` — кодирует `value` в буфер, возвращает число записанных байт.
- `bool TryDecode(ReadOnlySpan<byte> source, out int value, out int bytesConsumed)` — декодирует VarInt из непрерывного участка памяти. Возвращает `false` при неполных или битых данных.
- `ReadStatus TryRead(ref SequenceReader<byte> reader, out int value)` — декодирует VarInt из `SequenceReader<byte>`, продвигая позицию. Используется внутри `PacketFrameReader` и `PacketPayloadReader` для работы с фрагментированными данными без копирования.
