# VarInt — целое переменной длины

VarInt — это кодирование целого переменной длины, которое используется по всему протоколу Minecraft: для длин пакетов, ID пакетов и других числовых полей. Это то же самое, что **LEB128** (Little-Endian Base 128).

## Зачем переменная длина

Маленькие числа встречаются часто (длины пакетов, ID). Фиксированный `int32` в 4 байта тратил бы место впустую для значений, укладывающихся в один байт. VarInt использует 1 байт для `0..127`, разрастаясь до 5 байт только для очень больших или отрицательных значений.

## Битовая раскладка одного байта

```
бит:    7  6  5  4  3  2  1  0
      ┌───┬─────────────────────┐
      │ C │      данные (7)     │
      └───┴─────────────────────┘
        ↑
       continuation: 1 = «есть ещё байты», 0 = «последний»
```

- **Бит 7** — флаг продолжения. Выставлен → за этим байтом следует следующий.
- **Биты 0–6** — 7 бит полезных данных.

Данные идут **little-endian**: первый байт несёт **младшие** 7 бит, следующий — биты 7–13, и так далее.

## Разбор на примере: кодирование 300

Режем 300 на 7-битные куски с младшего:

```
300 = 0x12C = 1_00101100  (9 бит)
       режем по 7 бит с LSB:
       ┌─────────┬──────┐
       │ 0101100 │  010 │   ← куски (младший слева)
       │  =44    │  =2  │
       └─────────┴──────┘

накидываем continuation:
  байт 0: 1 | 0101100 = 0xAC   ← «есть ещё»
  байт 1: 0 | 0000010 = 0x02   ← «последний»

итого: [0xAC, 0x02]
```

Декодирование — обратный процесс, каждый байт вносится со сдвигом:

```
байт 0 = 0xAC → continuation выставен   → данные = 0xAC & 0x7F = 44  (биты 0..6)
байт 1 = 0x02 → continuation сброшен     → данные = 0x02 & 0x7F = 2   (биты 7..13)

значение = 44 | (2 << 7) = 44 | 256 = 300  ✓
```

Маски в ходу: `0x80` (continuation), `0x7F` (данные), сдвиг по 7 на байт.

## Краевые случаи

| Значение | Кодировка | Почему |
|----------|-----------|--------|
| `0` | `[0x00]` | Один байт, continuation сброшен. |
| `127` | `[0x7F]` | Максимум в один байт. |
| `128` | `[0x80, 0x01]` | Не влезает в 7 бит — нужен второй. |
| `-1` | `[0xFF, 0xFF, 0xFF, 0xFF, 0x0F]` | Знаковый int32 → все 5 байт. |
| `int.MaxValue` | 5 байт | Предел. 5-й байт несёт только 4 бита (биты 28–31). |

Последняя строка — причина, по которой декодер ограничен 5 байтами: если после 5-го байта continuation всё ещё выставлен, данные битые и декодирование падает.

## API

VarInt живёт в `Verstack.Protocol` как статический класс с методами:

- `GetByteCount(int)` — сколько байт займёт значение (без записи в буфер).
- `Encode(int, Span<byte>)` — записывает значение, возвращает число записанных байт.
- `TryDecode(ReadOnlySpan<byte>, out int, out int)` — читает значение; возвращает `false` при частичных/битых данных вместо исключения (частичные чтения нормальны в потоковом I/O).

См. `src/Verstack.Protocol/VarInt.cs`.
