# Login

Фаза Login — шаг после Handshake, на котором клиент сообщает, кем он хочет быть, а сервер проверяет это и пускает его в игру. Сервер попадает сюда по `nextState = Login` из Handshake; клиент шлёт Login Start, дальше идёт обмен шифрованием, сжатием и Login Success.

Сейчас реализован только вход в фазу и разбор Login Start: имя и UUID сохраняются на соединение, ответа сервер пока не отправляет. Шифрование, сжатие, Login Success и online-mode аутентификация — следующие подэтапы; их здесь нет.

## Типы пакета

| Тип | Роль |
|---|---|
| `LoginStartPacket` | DTO — имя, UUID |
| `LoginStartPacketParser` | Парсер — payload Login Start → DTO |

DTO — `readonly struct` с двумя полями: `Username` (строка, которую клиент заявил) и `Uuid` (тип `Uuid` из Protocol, 16 байт big-endian). UUID, который клиент прислал, не окончательный: в online-mode сервер подменяет его на UUID от Mojang в Login Success. Сейчас сервер хранит присланный.

Парсер — `static class`, читающий тело пакета через `PacketReader` (после packet id, потреблённого диспетчером). Без валидации имени: парсер читает произвольную строку, проверка длины и допустимых символов — семантика онлайна, не wire-формат.

## Формат на проводе

```
Login Start (клиент → сервер):  [0x00][VarInt(len)][UTF-8 имя][16 байт UUID, BE]
                                  ↑ packet id 0x00 в Login-фазе
```

Поля:

| Поле | Тип | Примечание |
|---|---|---|
| name | length-prefixed UTF-8 | максимум 16 символов по протоколу |
| uuid | UUID (16 байт big-endian) | сгенерирован клиентом; не дефис-строка |

Поля подписи чата (timestamp, public key, signature), бывшие в Login Start в 1.19.x, в 1.21.x убраны — они уехали в фазу Configuration. Пакет минимален: только имя и UUID.

## Что делает сервер

Диспетчер по `(Login, 0x00)` разбирает Login Start, сохраняет имя и UUID в поля соединения и возвращает `Keep`. Подробности роутинга — в [Диспетчере](dispatcher.md). Ответ сервера (Encryption Request / Set Compression / Login Success) не реализован, поэтому клиент висит и закрывается по таймауту — это ожидаемо для текущего шага: он проверяет вход в фазу Login и корректность разбора.
