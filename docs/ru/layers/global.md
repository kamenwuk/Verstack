# Global

GLOBAL-мир — общий корень, виден всем слоям, сам никого не знает. Не работает с сокетами и пакетами фаз; его роль —
хранить то, что нужно остальным: информацию о сервере, синхронизируемые реестры, ассеты, константы мира/спавна, общие
модели игрока.

Реализация — `GlobalLayer : ServerFeatureLayer` (`Scope = GLOBAL`). Не запрашивает чужие миры (`GetVisibleScopes` пуст),
никуда не передаёт игроков (`GetNextScope` — пусто, `GetHandoffPolicy` — `null`). Его единственная система —
`UpdateServerInfoSystem`.

## ServerInfoCacheStore

Кэш статуса сервера для ответа на пинг (Status-фаза): MOTD, лимит игроков, версия/протокол, счётчик онлайна. Хранит
готовый JSON ответа (`_cachedStatusJson`) с dirty-flag: при изменении онлайна (`SetOnlinePlayers`) флаг ставится, но
JSON не перестраивается тут же — это делает `UpdateServerInfoSystem` раз в секунду
(`SERVER_INFO_UPDATE_INTERVAL`). Ленивый `GetStatusJson` пересобирает JSON, если пинг пришёл до первого тика.

Задаётся параметрами конструктора в `GlobalLayer`: MOTD, max players, `"26.2"` (версия), `776` (протокол).

## SyncedRegistryCatalog

Статический каталог синхронизированных реестров Minecraft 26.2 (29 шт.). Используется в Configuration-фазе —
`KnownPacksBundle` отправляет клиенту Registry Data для каждого реестра. Содержит:

- `RegistryIds` — байтовые идентификаторы реестров (`"minecraft:dimension_type"` и т.д.).
- `MandatoryEntries` — обязательные записи для каждого реестра (`"minecraft:overworld"` для `dimension_type` и т.д.).
  Для опциональных реестров массив пуст.
- `RegistryType` (`enum : byte`) — типобезопасный индекс (29 значений), порядок **строго совпадает** с индексами обоих массивов.
- `GetId`/`GetEntries` — прослойки доступа по enum.

Каталог — единственный источник правды о том, какие реестры и записи сервер обязуется синхронизировать. Сами данные
реестров (контент записей) загружаются из ассетов через `Verstack.Shared.Assets`.

## Assets — владелец

Global — единственный слой, через который остальные получают доступ к скомпилированным ассетам. Загрузка выполняется
через `Verstack.Shared.Assets` (`AssetCatalog` и кэш-буферы); пайплайн компиляции данных описан в
[shared/index.md](../shared/index.md). Слои читают данные реестров/тегов только через этот путь, не напрямую.

## Константы мира и спавна

`SpawnConstants` и `WorldConstants` — статические параметры стадии Play:

- `SpawnConstants`: тип/имя измерения спавна (`minecraft:overworld`, id 0), координаты блока спавна (для компаса и
  телепорта входа), yaw/pitch. Координаты выведены так, чтобы стоп игрока стоял на поверхности FlatGenerator без
  проваливания.
- `WorldConstants`: дальности прорисовки/симуляции, игровой режим при входе (creative по умолчанию).

Используются в бандлах Join (Realm) — `JoinSpawnPointBundle`, `JoinLoginBundle`.

## Модели игрока

В `Layers.Global.User` лежат общие `readonly struct`-модели, которые не привязаны к конкретному слою:

- `NetworkSession` — параметры подключения: версия протокола, IP, адрес/порт сервера из Handshake.
- `UserProfile` — идентификация игрока: UUID, имя, локаль.

Эти типы переезжают между слоями через `EnterRealmHandoffData` (`BridgeHandoffData`-наследник в Global): Gateway
собирает их при логине, передаёт в Realm через [Bridge](../engine/bridge.md), Realm сеет в свой `UserSessionCacheStore`.
Хранение в Global — потому что оба слоя видят определения типов, но каждый держит свои экземпляры в своём кэш-сторе.
